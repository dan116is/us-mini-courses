# Lesson 4 — Take $9–$29 without building a store

**Time:** 60–90 minutes  
**Output:** A payment path you can complete yourself as a test (send $0 if you must dry-run the email; better: a $9 test from a second wallet or a friend who knows it is a test).

## Principle

A store (Shopify, Gumroad, Stripe Payment Link) is allowed if you already have one. This lesson assumes you **do not**, and you still want a dollar this week. The pattern is: **public price + public destination + email fulfillment.**

This course uses that pattern: USDC on Base, memo = slug, files by email.

## Path A — USDC on Base (matches this publisher)

Buyer instructions to publish:

1. Amount: **9 / 19 / 29 USDC** (not ETH).
2. Network: **Base** (chain ID 8453). Wrong network can lose funds; say this twice.
3. Address: yours, as a full string they can copy. Test-copy it yourself.
4. Memo / note: a **slug** you choose (`move-in-checklist`). If the wallet has no memo field, they put the slug in the order email.
5. Order email: they send **tx hash**, **from-wallet**, **delivery email**.
6. You send the file when the tx is confirmed on Base.

Write the chain name in bold. USDC exists on many chains; Base is not Ethereum mainnet.

**You** need a Base-capable wallet and a way to see the USDC transfer. If you cannot operate that yet, use Path B this week. Do not learn a new chain on Thursday night while the PDF is unfinished.

## Path B — US card rail you already have

If you have Venmo/PayPal/Cash App business features or a Stripe Payment Link from an old attempt, use **one**. Publish:

- Exact username/link
- What note the buyer must include (SKU slug)
- That friends-and-family vs goods-and-services may affect protection — state what you actually use; do not pretend you are a card network.

If you do not have any of these live, do not spend the week applying for new merchant accounts. Path A or a single Payment Link if it already exists.

## Fulfillment mailbox

Use an inbox you check on weekdays. A dedicated alias is nicer (`orders@`) but Gmail plus a filter on subject `order` works.

**Order email template (buyer-facing, on the sales page):**

```
To: [your orders email]
Subject: order [slug]

- Amount sent:
- Network / method:
- Tx hash or receipt:
- Wallet or account I sent from:
- Email to receive the file:
```

**Your send template:**

```
Subject: Your file — [title] v1.0

Attached (or linked): [filename]
License: personal / one team ≤5. No resale of the PDF.
If it doesn’t open, reply to this thread. I resend.
This email is the product. There is no login.
```

Save a folder `orders/YYYY-MM-DD-email-slug/` with the tx note. That is your books starter; your CPA still does the taxes.

## Test once

Before you tweet anything:

1. Pay your own SKU with the smallest price (or have a friend pay $9).
2. Follow your own instructions literally. Fix the first sentence that confused you.
3. Send the file from the orders mailbox, not your personal rambling thread.

If you cannot complete a test, you do not have a checkout. Fix that before “launch.”

## Chargebacks, refunds, honesty

Digital goods are messy. Your posted policy: **resent if corrupt; otherwise final.** Still, if a buyer got the wrong file, make it right. Do not argue tone. Do not offer a “coaching call” to avoid a $19 refund — that call costs more than $19.
