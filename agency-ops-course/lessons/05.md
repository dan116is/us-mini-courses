# Lesson 5 — Four-week install: run it until it is boring

**Time:** Four calendar weeks  
**Output:** A shop that can survive one sick Tuesday without a Slack pile-up.

## Success looks dull

You win this course when Monday Plan is slightly annoying and invoices leave on Friday without a Sunday scramble. Not when you “feel aligned.”

No revenue target is attached. The operating rhythm protects delivery and cash **you already have**. Growth is optional and later.

## Week 1 — Install without improving

- Run the three meetings even if the scoreboard is ugly.
- Use only the three SOPs from Lesson 2. Do not write a fourth.
- Owner keeps the WIP cap even if it feels rude.
- End of week: list what you skipped. That list is Week 2’s only improvement candidate.

**Common Week 1 failure:** rebuilding Notion. Banned. The scoreboard is one tab.

## Week 2 — One bottleneck

From Friday’s repeated “what was slow” sentence, rewrite **one** SOP. Typical: first reply or invoice follow-up.

Add nothing else. If inbound is spiky, add a second inbox check time — that is still SOP A, not a new program.

**Check:** Did every active job have a dated next action by Monday 9:40? If no, the Plan meeting is too polite. Read the rows out loud.

## Week 3 — Client-visible cadence

Pick one weekday (often Thursday) as **update day** for every active delivery client. Same day every week. A short email: done / next / waiting-on-you. If you need language, the companion course `client-email-course` is built for that; you can also write a five-line version:

```
Subject: Weekly — [Job] — week of [date]

Shipped this week:
-
Next week:
-
Waiting on you:
-
Anything that slipped, said plainly:
-
```

Send even when the week was thin. Silence is how clients invent stories.

## Week 4 — Backup drill

Pick a 4-hour window the owner is unavailable (real errand). The backup follows SOP A and SOP C from the pages. Owner may not pre-clear every email.

Afterward, 15-minute debrief: which sentence in the SOP was missing? Write it in. That is the test. If the backup had to call you, the SOP is still a memo to yourself.

## Monthly 40-minute retro (after Week 4, then monthly)

1. Four Fridays of numbers: invoiced, collected, overdue, hours.
2. WIP cap: did you break it? Why, in one line each time.
3. Kill or keep each SOP. If unused, it was the wrong SOP — replace from the work map, do not guilt-keep.
4. One change for the next month. Write it on the scoreboard header.

## When to hire vs when to raise prices

This is judgment, not a formula:

- If WIP is full **and** inbound is qualified **and** you are turning away fit work two weeks in a row, you have a capacity problem. Contractor hours or a price increase are the levers. Hiring a full-time person is a separate decision (benefits, unemployment insurance, wage/hour rules — talk to your CPA / employment counsel).
- If WIP is full because jobs never finish, you have a definition-of-done problem. Do not hire. Fix SOP B (scope lock) and review rounds.

## What this course will not do

- It will not replace a bookkeeper.
- It will not make a bad offer sell.
- It will not give you a $5,000/month guarantee.
- It will not run the meetings if you cancel them for “real work.” The meetings are the real work for an operator.

## Final checklist

- [ ] Work map from three real jobs
- [ ] Three one-page SOPs with backups
- [ ] Scoreboard with WIP cap in the header
- [ ] Mon/Wed/Fri holds for the next month
- [ ] Owner deep-work blocks
- [ ] One backup drill completed
- [ ] Update weekday chosen

When those boxes are true, stop taking courses about operations and go back to selling and shipping.
